# 开盘、午盘和收盘报告的正文

港美两市 Mode 6 共用。先写读者能核对的事实，再说它怎么影响判断。程序给出价格、涨跌、盈亏、占比、集中度、因子值、排名、触发位、日期差、相关性、回撤、β/Vol、回执和计数。模型选因子，判断情绪与消息、取舍归因、讲故事、提反方和证伪条件，说明信心与动作。情绪里的数字也照字段引用；需要新计算时只用本次 compute 回执。

- **▎情绪面**。先讲异动归因，就写在这一段里，出处和时点嵌在对应句子里。`anomalies` 有哪些票就写哪些票，同向且有共同来由的可以合写。按 `mover_news.halts` 先交代停牌，说明已知原因和复牌时间，未公布就明说。对照 `mover_news`，只有 `tier=primary` 且 `signal=interrupt` 的消息可作硬催化，`tier=supporting` 只作背景。主公告也只能支持有依据的归因。
  - `source_class` 换成读者熟悉的说法：`exchange_filing` → 交易所公告，`hkexnews_filing` → 港交所公告，`sec_filing` / `sec_filing_mirror` / `sec_fulltext` → SEC 文件，`finnhub_filing` → 公司公告（Finnhub），`market_flash` → 市场快讯。引用整条资讯用 `|cite`。
  - `no_recent_filing` 先查 `known_catalysts`，有已知催化就说明公告窗口里没更新、已有消息仍可能相关；没有就说暂时无法归因。`index_fund_no_issuer` 看成分和板块。`degraded` 说哪份资料没取到；来源没回答和查无新消息是两种情况。`mover_thesis` 有 `triggered` 或 `watch` 红线时，用一句话交代红线和这次异动的关系。这是归因语境，不是操作许可。catalyst 评级只是登记策略意见。
  - 逐票查 `live_information.summary`。有本场资讯或同日时点不明的公告时，在这一段为每只相关票至少引一条，优先当前公告。用原记录的 `|cite` 保留出处、发布时间和新旧标签。旧新闻只在仍有解释价值时引用，按旧闻写。`live_information.degraded` 点名没取到的源。再用 `peer_scan` 的 Top 5 和持仓与同业的同场今日/5 日涨跌核对比较，正文留会改变判断的差别。篇幅紧时先砍板块全景的细节，保留异动和逐票资讯。
- **▎技术面**。读 `signal_count` 和信号明细，说哪项价格行为影响操作时机；信号没变也可以说清继续看什么。按 `quote_coverage` 点名未刷新的票，旧报价只作背景。
- **▎操作建议**。开头用 `plan_context` 做计划对账。没取到就明说未对账，查到空计划才说没有未执行决策。纪律动作照原条件和 MOO 等委托方式写；改变计划要说明新事实和理由。计划持有、止损豁免、未结风险按计划、策略和账本写；用户已撤销的单按已结案说，候选去向只是观察。股数和触发线由计划表给出。须写 **▎风险提示** 时，说这次哪项敞口或红线值得留意，按风险账本说核实过的状态。

三段内就近引用可核对的凭据。一段讲一件事，异动较多时可以拆成几段，每段仍留在原小节。写判断时，用自然语言交代依据；引用数值才在该数值的位置填确切叶字段，如 `[[/ctx/holdings/00100/today_change_pct]]`。引用资讯只填整条记录，如 `[[/ctx/live_information/summary/00100/0|cite]]`。形如 `[[/ctx/holdings]]` 的对象、整张表和路径本身都不是出处。数组从零编号，代码含数字时填同代 `ticker` 引用；支持的显示方式是 `|cite`、`|count` 和 `|status`。另算时只用本次 `clawock tool compute` 回执。读者只看得到这条微信，把字段名和管线术语翻成平时说法。长度由你自己判断，覆盖该交代的事实类别就可以停。

如需补查行情资讯，优先内置搜索或 DeepSeek。Tavily 仅在开盘、收盘或有真实事件时使用，带 `--bucket report`。
