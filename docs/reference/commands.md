## Installed commands / 已安装命令

**88 commands** are installed by the single `clawock` distribution: 11 lifecycle subcommands built in `src/clawock/cli.py`, 65 packaged `clawock <utility>` subcommands and 12 standalone scripts. `clawock --help` offers the first two groups (76 subcommands). 48 of the registry commands collect or compute information and appear under the layer they feed; the remaining 29 publish, gate, record or schedule, and are listed with the reason they are not collection.

本节由生成器从 `clawock.cli.build_parser()`、两份 registry 与 `config/information-layers.json` 推导，不手写；新增或删除一条命令，这张表自己会变。

## 手写细节 / Hand-written detail

Lifecycle boundaries, context/generation IDs and delivery ownership live in
[the harness contract](../architecture/harness.md); the
[intraday contract](../architecture/intraday-agent.md) owns slot-specific rules.
Provider coverage, credentials and missing-data semantics live in
[data coverage](data-coverage.md) and [tool operations](tool-operations.md).

### Generation-bound postflight calls

The model writes prose to a file; the harness assembles the data block. Both
calls require the preflight's context ID, so a different generation cannot be
silently combined with that prose:

- **`clawock report postflight --market {hk|us} --phase {open|mid|pm|close} --context-id ID --text-file PATH`**
- **`clawock intraday postflight --market {hk|us} --context-id ID --text-file PATH`**

### Arguments and operational boundaries

The installed parser owns syntax and defaults: use `clawock COMMAND --help`,
or `clawock COMMAND SUBCOMMAND --help`. The inventory above names the module
behind each command; this page does not maintain a second copy of its parser.

- **SEC filings:** `clawock filings TICKER` lists recent forms; `--filings
  10-K,10-Q` selects forms, `--financials` reads XBRL concepts, `--form4` and
  `--13f` select ownership filings, and `--json` selects structured output.
  Access configuration and request limits belong to [data coverage](data-coverage.md#sec-access).
- **FX:** `clawock fx` supplies the dated conversion rate;
  `--convert AMOUNT FROM TO` converts explicitly. Currency legs need that rate
  before aggregation; cache and fallback status are part of the result.
- **Book writes:** refresh commands update quotes. Record broker truth in
  `holdings[].trades[]` and the broker-owned position/cash leaves, then run
  `clawock reconcile`. It derives totals and checks conservation; it does not
  infer a trade. `audit-resettle` is read-only unless `--write` is supplied.
- **Decision records:** `clawock record` appends a judgment, never an order.
  Its default market/currency are HK/HKD; US records require US/USD explicitly.
  The schema, action vocabularies and validation belong to the
  [mind ledger](../decision-mind-ledger.md).
- **Risk and research:** `risk ack`, `override` and `confirm` write the risk
  ledger; acknowledgment is distinct from evidence of resolution. Thesis,
  earnings and entry-gate artifacts feed the [research work queue](../operations/research-cadence.md).
  `research --check` fails invalid artifacts, not ordinary due work.
- **Dashboard builds:** default builds use the workspace. `--previous` is an
  explicit published-generation input for a checkout missing context sidecars;
  `--out-dir` stages outputs away from public paths. `--skip-if-unchanged`
  skips unchanged projections, not required slot heartbeats. Publishing and
  ownership are in [the harness](../architecture/harness.md) and
  [data plane](../architecture/data-plane.md).
- **Scorecard provenance:** verification defaults to the recorded source ref;
  explicit `--ref` or `--ledger` selects another source. Brief live snapshots
  carry their own archived inputs; see [capability ownership](../architecture/harness.md#capabilities-one-owner-any-entry).
- **Evaluation:** parameter search, run cards and cost assumptions are owned by
  [strategy plugins](../architecture/strategy-plugins.md). A retrospective
  result or a `--no-card` run does not authorize a live policy change.

### Cron map

Schedules, job identities and watchdog mapping are generated in
[cron schedules](../operations/cron-schedules.md) from
`config/cron-schedules.json`. Payload text lives in `config/cron-payloads/`.
Check with `python3 ops/host/sync_cron_payloads.py --json`; use `--apply` only
when synchronizing the live contract. The synchronizer rejects ambiguous jobs
and in-flight changes, then reads back each applied patch.

### Cron 运行历史（自动 + 手动跨 job 聚合）

`openclaw cron runs` 必须带 `--id`，且单 job 视角。跨 job + 自动调度 + 手动 trigger 一起看用：

```bash
bash ops/host/check_crons.sh                 # 最近 20 次（auto + manual 混排，HKT 倒序）
bash ops/host/check_crons.sh 50              # 最近 50 次
bash ops/host/check_crons.sh --status error  # 只看失败
bash ops/host/check_crons.sh --kind cron     # 只看自动调度
bash ops/host/check_crons.sh --job 港股       # 按 job 名子串过滤
bash ops/host/check_crons.sh --full          # 摘要不截断
bash ops/host/check_crons.sh --json          # JSON 输出（喂给后续 pipeline）
```

运行历史同样优先经 OpenClaw CLI 读取；旧 `cron/runs/*.jsonl` 只作为迁移前 fallback。
脚本本体 `ops/host/cron_runs.py`。
