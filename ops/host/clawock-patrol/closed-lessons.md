# 以前的 loop issue 为什么被关（提 issue 前逐条对照）

08-25 以来 loop 开的 239 条 issue 里 90 条没有 PR 就关了（2026-09-17 统计）。草稿落进下面任何一条就不要提。
每条的真实案例（issue 号与关闭理由）在 `closed-lessons-examples.md`，写「对照已关」或拿不准时再读。

1. **「没人用 / 没清理 / 没校验」其实有，只是没搜到**（最常见）——必须 `git -C /root/wt-patrol grep -n '<符号>'`
   搜整个仓库（src、ops、skills、site、tests、config、examples、.github、docs），字段名再搜字符串形式和 bundle/SKILL 引用。查不到 ≠ 不存在。
2. **读的是过去**：注释、docstring、旧 issue 描述的是已修掉的状态——必须 `git log -S` / `git blame` 看何时为何这样写，并查 open/closed issue 是否处理过。
3. **有意设计被当成缺陷**——必须读目标代码前后至少 40 行和附近注释；注释解释过的取舍不是缺陷。
4. **影响是乘出来的，不是量出来的；或者修了不值**——不提纯重构、拆文件/函数、import 耗时、magic number、「抽注册表」；
   性能只在量出秒级/MB 级/真实失败的用户可见代价时提，并说清修法不引入正确性风险。
5. **判据红错了地方**（拼写、单行正则找跨行代码、判据自己崩）——判据先打印实际读到的值再断言，断言 issue 说的那件事本身，自己先跑一遍对结论。
6. **描述的机制不存在**——把调用链从入口（CLI / workflow / cron）顺到你说的那一行，写进「为什么是问题」。
7. **同一件事拆成多条 / 重复**——一个根因只提一条；已有 open 或已关的同根因 issue 不再提。
8. **产品边界外**——clawock 是决策工作流插件 + 可验证 harness，不下单、不搜参数；不提新功能、竞品移植、方向性建议，只提「现有功能今天是坏的」。
