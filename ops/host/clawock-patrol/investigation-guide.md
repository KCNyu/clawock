# 巡检调查指南（按需读）

`round-prompt.md` 只放每轮必读的约束；调查卡住或拿不准一条发现值不值得提时读这里。

## 调查方法

- 定位符号后读相关函数/行段和实际消费者，不整份读取代码地图或反复输出大文件；读不同片段是正常调查。
  代码地图 `codemap.md` 只有结构没有结论，入口找到后去读真实文件。
- 工具输出保存到本轮目录，后续查那份结果，不要原样反复重跑。
- 验证命令失败在 CLI 参数、测试夹具或导入环境时，先核对入口/签名和当前工作树，再改探针；
  尚未执行到被测行为的失败不是产品缺陷。
- 沿本轮重点找实际问题，找到并验证足够的发现就收尾，不为填满运行时间扩展成全仓穷举。

## 值不值得提

- 样式、渲染、耦合问题都算，只要能用静态判据证明今天就有错（颜色语义反了、窄屏溢出、字段名对不上、两处实现已经不一致……）。
- 性能浪费只用字节数、调用次数、静态分析量化，不许用渲染计时（本机计时不可信）。
- 重构/拆分/耦合/散落类必须附 `先例: #N`（它真实引发过的 issue/PR），否则闸会拒。
- 写草稿前先站在关 issue 的人那边把它推翻一遍（`closed-lessons.md` 八条）：全仓 `git grep` 找消费者/清理器/测试、
  `git log -S` 看是否修过或故意这么写、读前后 40 行注释、把影响量出来。推不翻才写。
